# SNP Anonymizer — правила разработки

- Русский, кратко. Работать в этом репозитории, модель `C:/Git/inplan-data-model` читать без изменений.
- Runtime полностью offline: без PostgreSQL, Docker, Python на пользовательской машине и сетевых запросов. Desktop Tkinter, Windows EXE.
- Никогда не добавлять в Git клиентские входы, результаты, `.snpanon`, SQLite или логи со значениями. Тесты только синтетические.
- sys_id не экспортировать как значение. Количества/цены/даты сохранять; бизнес-идентификаторы заменять по общим доменам FK.
- Память ограничена: буферы и кеши ограничивать байтами, SQL INSERT/COPY читать потоково. Память не должна расти с размером входа.
- SQL не исполнять; неизвестные формы блокировать с безопасной ошибкой. Не копировать исходные SQL, комментарии, DEFAULT и бинарные файлы в выдачу.
- После изменения: `python -m pytest -q`, smoke GUI; после изменений упаковки — собрать и проверить EXE. Перед коммитом code-reviewer, в конце verifier.
- Большие рефакторинги: сначала planner. Источник модели обновлять через `tools/snapshot_model.py`.
