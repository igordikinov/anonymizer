## Непроверенное и ограничения

Полный restore в PostgreSQL, совместимость с реальным клиентским стендом, высокая кардинальность и большой единый INSERT не проверены. Runtime PostgreSQL/Docker не добавлять для обхода этого ограничения.

Дамп содержит реконструированные таблицы и данные; функции, триггеры, права, DEFAULT, индексы и исходные ограничения не переносятся. Задача GLM-001 добавляет **метаданные и проверку** групп FK; перенос ограничений в DDL не входит в неё.

Reader поддерживает стандартный текстовый COPY и INSERT с литералами. Массивы, пользовательские типы, COPY CSV/binary, INSERT expressions и UPDATE/DELETE остаются вне версии 0.1. Не обещать произвольный SQL backup.

CSV NULL — `\N`, пустое поле — пустая строка; decimal/date NULL не угадывается. Обычный CSV создаёт полную таблицу модели. NUMBER без fractional precision экспортируется в unconstrained numeric. Отсутствующие master — `target_not_in_input`, исходные дефекты не исправляются.

JSON меняет строки/нестандартные имена свойств, сохраняя числа/ISO-даты и форму. Профиль семантики клиентских JSON-расширений не согласован; перед расширением проверять реальные типы и ссылки на синтетике. `.snpanon` не зашифрован и содержит исходные значения, выдавать его вместе с результатом нельзя.

## Карта кода и ownership

| Модуль | Ответственность |
|---|---|
| sql_reader.py | Потоковый lexer, COPY/INSERT, извлечение DDL/PK/FK; SQL не выполняется |
| csv_reader.py, metadata.py, resources/model.json | Типы CSV, manifest, snapshot модели |
| store.py | Дисковый spool, поля, master-root; внутренние контракты общие |
| canonical.py, mapping.py, json_data.py | Точность identity, постоянные карты и правила |
| validation.py | Контроль сохранения, FK и ключей; требует групповой проверки |
| exporters.py, pipeline.py | Три согласованных экспорта, publication/cleanup/report |
| gui.py, cli.py | Окно/CLI поверх одного pipeline, прогресс/отмена |
| tools/, packaging/ | Snapshot, benchmark, preflight, build и smoke EXE |

Для каждого общего контракта назначить одного писателя. GLM-001 затрагивает reader/store/validator/manifest, поэтому её реализует один worker, а не несколько конкурирующих агентов.

## Окружение и проверяемые команды

На исходной машине: Python 3.12.14; pytest 9.1.1; PyInstaller 6.22.3; psutil 7.2.2; pglast 8.5; bd 1.2.2. Это наблюдение, не фиксация обязательных версий. Минимум Python — 3.11 по pyproject.toml. Сборка EXE — на Windows.

Из корня репозитория:

```powershell
.\tools\preflight.ps1 -RequireClean -RequireExe
.venv\Scripts\python.exe -m pytest -q
.venv\Scripts\python.exe -m anonymizer --smoke-gui
.\tools\build_windows.ps1
.venv\Scripts\python.exe tools\smoke_exe.py dist\SNP-Anonymizer.exe
```

Preflight по умолчанию ничего не устанавливает, не создаёт venv/Beads, не меняет Git/hooks/config и не запускает тесты/benchmark. Если EXE отсутствует в свежем клоне, запустить без `-RequireExe`; отсутствие обязательного Python/dev-module — FAIL. `-PythonPath` позволяет указать другой подготовленный interpreter. Bootstrap — по README, только при необходимости, с проверкой exit code.

Не запускать 1 ГиБ benchmark для документационных/мелких правок. Повторять при изменении потокового reader, spool, кешей, алгоритма проверки или unresolved memory/performance concern. Для GLM-001 сначала узкие синтетические fixtures, затем согласованный контроль объёма; не выдавать небольшой прогон за 1 ГиБ.

## Проверки и отчёт GLM

После нетривиальной правки: planner → worker с ownership → тесты → read-only code-reviewer → verifier. Если оболочка не поддерживает отдельные контексты, использовать отдельные сессии; иначе отметить только самопроверку и оставить независимый gate открытым.

Итог: что изменено, BR/AC, файлы, команды/exit codes, тестовые результаты, остаточные ограничения, Git HEAD/diff, статус самостоятельной/независимой проверки. Не включать оригинальные данные, карты или токены. При готовом результате и действующей авторизации commit/push выполнять после ревью; не reset/rebase чужую работу.
