# Готовый стартовый промпт для GLM

Скопируйте блок в новую сессию GLM, открытую в корне своего клона `igordikinov/anonymizer`. На исходной машине это `C:\Git\anonymizer`. Не нужны история этого чата, API-ключи в репозитории или заранее заданный endpoint.

```text
Продолжи разработку SNP Anonymizer в текущем репозитории.

Сначала прочитай AGENTS.md, README.md, docs/input-contract.md,
docs/handoff-glm.md, docs/tasks/GLM-001-composite-fk.md и
.agents/roles/orchestrator.md. База реализации — main@8c4143b;
пакет передачи добавлен отдельным коммитом, поэтому проверь текущий HEAD/diff.

Выполни tools/preflight.ps1 из корня. Он read-only. Если .venv отсутствует,
следуй bootstrap в README без перезаписи существующего окружения.
В свежем клоне dist/SNP-Anonymizer.exe может отсутствовать — это ожидаемо.
Не создавай Beads: трекера сейчас нет. Не меняй endpoints, hooks, shell config,
репозиторий модели, клиентские данные или подключённые БД.

Первая задача — GLM-001: хранить группы составных FOREIGN KEY и проверять
полные кортежи на диске. До правок воспроизведи описанный дефект на синтетике.
Прочитай canonical роли planner, worker, code-reviewer, verifier.
Подготовь короткий план с BR/AC и ownership; один worker владеет общими
reader/store/validation/manifest контрактами. Не откатывай чужие изменения.

Реализуй GLM-001, не расширяя её автоматически до GLM-002 или новых SQL-форматов.
Сохрани offline runtime без PostgreSQL/Docker, точность количеств/цен/дат,
постоянные карты проектов, пропуск sys_id и три согласованных формата результата.
Входящие исходные нарушения FK показывай как before/after; отсутствующий master
не считать подтверждённой целостностью. Все fixtures — синтетические.
Не выводи клиентские значения в логи/чат и не добавляй их в Git.

Прогони подходящие тесты, весь suite и smoke GUI. После изменения runtime
собери Windows EXE и выполни tools/smoke_exe.py. Проверки объёма делай по
контракту передачи; не называй старый benchmark новым результатом.
Нужны независимые read-only reviewer/verifier в отдельных контекстах.
Если твоя оболочка не умеет их запускать, используй отдельные сессии;
при отсутствии такой возможности честно оставь независимую проверку открытой.

Отчитайся: изменённые файлы, выполненные AC, команды/exit codes,
новые проверки, ограничения и Git HEAD/diff. Коммит/push — по действующей
авторизации пользователя после ревью, без reset/rebase чужих изменений.
Не публикуй Release и не передавай .snpanon или исходные выгрузки наружу.
```
