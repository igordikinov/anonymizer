# GLM-001 — проверка составных FOREIGN KEY

Состояние: **карточка передачи, запланирована; не реализована и не claimed в трекере**. Основание: базовый код `8c4143b`. Зависимостей нет. Это первое задание продолжения.

## Проблема и доказательство

`sql_reader.py:426`, функции `apply_table_constraint`/`alter_constraint`, раскладывает составной FOREIGN KEY на `field['fk']` и теряет группу. `Validator.__init__` (`validation.py:73`) и `finish` (`validation.py:121`) формируют/проверяют отдельные колонки. Наличие каждой части ещё не означает наличие всей пары в одной строке. Дефект независимо воспроизведён при подготовке передачи для CREATE и ALTER: текущий отчёт ошибочно даёт 0/0 по обеим колонкам.

Синтетика: parent `(a,b) = ('A',1),('B',2)`, child `('A',2)`. Отдельно A и 2 существуют, но составной ссылки нет. Воспроизвести для CREATE и ALTER ADD CONSTRAINT (при необходимости исходный FK NOT VALID). Никакой SQL не выполнять — подать в существующий pipeline.

## Требование и критерии

| BR | AC |
|---|---|
| BR-01 Сохранить составную связь | AC-01 Каталог сохраняет ordered source columns, target schema/table/columns и MATCH semantics для CREATE и ALTER ADD |
| BR-02 Проверять исходную и итоговую целостность | AC-02 Дефект A/2 даёт missing_before=1 и missing_after=1; согласованная пара даёт 0/0; новая потеря ссылки блокирует выдачу |
| BR-03 Не ошибаться на NULL/частичной выгрузке | AC-03 MATCH SIMPLE: любой NULL исключает ссылку из missing. Отсутствующий target — явно непроверенная связь. MATCH FULL реализовать корректно либо явно отклонить до обработки |
| BR-04 Сохранить типы и сопоставление | AC-04 Numeric 123/123.0 и UUID variants сравниваются канонически, поля quantities/dates не меняются; разные схемы и self-reference протестированы |
| BR-05 Память ограничена | AC-05 Полные tuple keys/indexes находятся в SQLite; нет множества всех ключей в Python, есть byte-budget и отмена |
| BR-06 Удержать три формата | AC-06 CSV manifest roundtrip сохраняет FK-группы; старый manifest v1 и модель с отдельными FK остаются совместимыми, без угадывания составных групп |
| BR-07 Не изменить продуктовый scope | AC-07 Runtime offline, sys_id пропускается; FK на sys_id по-прежнему блокируется. Исходные constraints не добавляются автоматически в dump.sql |
| BR-08 Проверяемый результат | AC-08 Старые тесты и новые fixtures, GUI smoke, EXE build/smoke; независимые reviewer/verifier либо явно открытый gate |

Не сохранять исходные клиентские имена constraints в публичном manifest/report; достаточно внутреннего/нейтрального идентификатора группы. Проверка должна считать/показывать понятную единицу missing tuples/rows и описать её; не подменять её суммой missing отдельных колонок.

## Ownership

Один worker отвечает за `src/anonymizer/sql_reader.py`, `store.py`, `validation.py`, `exporters.py`, `csv_reader.py` и соответствующие synthetic tests. `metadata.py`/`pipeline.py` менять только при необходимости согласованного DTO/report; обосновать в плане. Политика mapping/industry/sys_id и GUI вне функционального scope.

Работник не один в кодовой базе: не откатывает чужие изменения. Общий metadata/manifest contract имеет одного писателя. Planner/read-only reviewer/verifier не редактируют файлы.
