# Связность основных таблиц SNP

Выберите **«SNP v1»** в поле «Профиль связности». Профиль согласует коды в 16 основных таблицах SNP и проверяет фактические CSV, `dump.sql` и `inserts.sql` после записи. Он работает и с галочкой «Обрабатывать без эталонной модели»: дополнительные колонки сохраняются, эталон не подключается обратно.

```powershell
.\distrib\SNP-Anonymizer.exe --input C:\data\snp_input --output C:\data\snp_anonymous_new --project C:\private\snp_connected.snpanon --bypass-model --connectivity-profile builtin:snp-v1 --require-integrity
```

SNP v1 и Optimizer v2 — отдельные профили. Они не объединяют карты между собой. Ресурсы SNP не включаются в домены `resource_prod`, `resource_stock` или `resource_transp`.

## Таблицы и общие коды

В профиль входят `item`, `loc`, `sku_attributes`, `mot`, `tlane_mot`, `tlane_prod_mot`, `res`, `res_attributes`, `rescapacity`, `prod_cap_req_sp`, `comp_req_sp`, `prodsource_sp`, `stock_levels`, `sp_demand`, `sp_demand_profile` и `demand_stream`.

| Объект | Поля, использующие общую карту | Префикс |
|---|---|---|
| Товар | `item` в перечисленных таблицах и `comp_req_sp.comp` | `item` |
| Локация | `loc`, `tlane_mot.locfr`/`locto`, `tlane_prod_mot.locfr`/`locto` | `loc` |
| Способ перевозки | `mot.mot`, `tlane_mot.mot`, `tlane_prod_mot.mot` | `mot` |
| Ресурс SNP | `res.res`, `res_attributes.res`, `rescapacity.res`, `prod_cap_req_sp.res` | `res` |
| Источник производства | `prodsource_sp.prodsource`, `comp_req_sp.prodsource`, `prod_cap_req_sp.prodsource` | `ps` |
| Поток спроса | `demand_stream.dmdstream`, `sp_demand.dmdstream`, `sp_demand_profile.dmdstream` | `ds` |
| Тип спроса | `sp_demand.demandtype`, `sp_demand_profile.demandtype` | `dt` |

Внутри исходной схемы один код объекта получает одну замену во всех объявленных полях. `item` и `comp` обозначают товар и используют общую карту. Одинаковая строка товара, локации и ресурса не объединяет эти разные объекты. По умолчанию коды разных исходных схем независимы; общий namespace требует явного объявления внешнего профиля.

Профиль также согласует общие роли единиц измерения, календарей и групп ресурсов **внутри этих 16 таблиц**. Эти три домена и проверки совпадений дополнительных ролей необязательны. Соответствующие внешние справочники `uom`, `sp_calendar_rules` и `sp_resgroups` в обязательный набор не входят. Отсутствие внешнего справочника не получает фиктивный PASS: профиль не объявляет проверку ссылок на такой справочник.

Примеры замен: `item_000001`, `loc_000001`, `res_000001`. Допустимое кодирование согласуется по длинам всех связанных полей. Для короткого поля может применяться компактный код; значения не обрезаются. Исчерпание допустимого пространства кодов блокирует выдачу.

## Типы и сохраняемые значения

При определении структуры CSV/XLSX поля текстовых доменов канонического SNP v1 трактуются как текстовые коды до обезличивания. Поэтому символьные и цифровые значения в `mot`, `res`, `prodsource`, `dmdstream`, `locfr` и других объявленных ролях не конфликтуют по типу. Ведущие нули и исходные текстовые различия сохраняются до замены. Формат даты Excel не применяется к этим кодам.

Это правило действует только для канонического SNP v1 и семантически такого же JSON. Одного совпадения `profile_id` недостаточно. Произвольный изменённый JSON сохраняет прежние правила определения типов. Optimizer v2 сохраняет прежние ограничения ресурсных полей.

Типы, явно объявленные во входном DDL или CSV-manifest, имеют приоритет. Профиль не превращает явно объявленный NUMBER в TEXT; несовместимый контракт блокируется до замены. Количества, цены, ёмкости, длительности, даты и периоды не входят в домены кодов и сохраняются. Десятичная запятая в числовом поле нормализуется в точку без float и округления.

`sys_id` очищается, `update_date_time` сохраняется, `change_author` становится `snp`. Политика системных полей имеет приоритет перед профилем.

## Что проверяется

Обязательный набор содержит 66 проверок: семь общих доменов, семь проверок совпадений отдельных ролей, 31 объявленную одноколоночную FK-связь внутри набора, 16 бизнес-ключей и пять проверок совпадений составных ролей. Ещё шесть проверок относятся к необязательным единицам измерения, календарям и группам ресурсов.

Составные роли проверяют сохранность точных совпадений:

- товар и локация, включая роль компонента;
- ресурс и локация;
- товар, локация и источник производства;
- исходная локация, целевая локация и способ перевозки;
- товар, локация, поток и тип спроса.

Эти проверки сравнивают BAG-проекции, включая повторяющиеся строки. Они **не объявляют новые составные FK** и не требуют наличия родителя там, где это не задано источником. Для фактических FK сохраняются точные пары строк и исходно несопоставленные ссылки. Исходные дефекты отражаются отдельно от результата преобразования.

Бизнес-ключи берутся из снимка модели без дополнения по сходству имён. NULL в них сравнивается по правилу `NULLS NOT DISTINCT`; исходные группы дублей сохраняются.

| Таблица | Бизнес-ключ |
|---|---|
| `item` | `item` |
| `loc` | `loc` |
| `sku_attributes` | `item`, `loc` |
| `mot` | `mot` |
| `tlane_mot` | `locfr`, `locto`, `mot` |
| `tlane_prod_mot` | `item`, `locfr`, `locto`, `mot`, `validfr`, `validto` |
| `res` | `res`, `loc` |
| `res_attributes` | `res`, `loc` |
| `rescapacity` | `res`, `loc`, `periodid` |
| `prod_cap_req_sp` | `item`, `loc`, `prodsource`, `res`, `date`, `periodid` |
| `comp_req_sp` | `item`, `loc`, `prodsource`, `comp` |
| `prodsource_sp` | `item`, `loc`, `prodsource` |
| `stock_levels` | `item`, `loc`, `periodid` |
| `sp_demand` | `item`, `loc`, `dmdstream`, `demandtype`, `periodid` |
| `sp_demand_profile` | `item`, `loc`, `dmdstream`, `demandtype` |

## Неполный набор и результат

Выбор профиля включает «Требовать проверку доступных связей». Передавайте нужный поднабор: наличие всех 16 таблиц не требуется. Профиль сохраняет общие коды между переданными таблицами и проверяет доступные части. Отсутствующая таблица или физическая колонка получает `NOT_CHECKED`; результат с неполным обязательным охватом публикуется как `UNVERIFIED_INTEGRITY`, в том числе при включённом флажке. Полный PASS не заявляется. Колонка, заполненная NULL, не считается отсутствующей.

В `report.json` и CSV-журнале названы конкретные недоступные объекты и причины. Например, если в `prod_cap_req_sp` есть `datefr`, но нет `date`, проверка ключа с `date` не выполняется; приложение не придумывает алиас. Пропущенная при чтении таблица отмечается отдельно от таблицы, которой не было во входе. Числа «проверено / пропущено» помогают оценить фактический охват.

При включённом требовании неподдерживаемая обязательная проверка, неизвестная причина пропуска или отсутствие обязательного набора остаются блокирующими. Внешний JSON с явной политикой `missing_target_policy: "block"` сохраняет запрет неполного набора при включённом требовании. Любой FAIL преобразования и незавершённое выполнение блокируют данные независимо от флажка.

`PASSED` означает полный PASS **обязательного объявленного охвата**, а не проверку всех внешних ссылок приложения. Проверяйте причины пропусков в `coverage`. При любом FAIL преобразования, незавершённой проверке или невыполненном требовании в новой папке остаётся только диагностический `report.json`; CSV/SQL и приватная карта не публикуются, PostgreSQL не подключается.

Карта замен по-прежнему содержит три столбца: «Домен», «Исходное значение», «Замена». Названия вроде «Товар (ITEM)» и «Ресурс SNP (RESOURCE)» показывают роль и связанные поля. Исходные значения и приватные имена схем остаются только в локальном проекте и отдельно выбранной карте, за пределами публикуемого пакета.

## Совместимость

Для SNP v1 создайте новый `.snpanon`, если прежний проект использовал Optimizer или другой профиль. Непустой проект без профиля нельзя автоматически перевести в профильный режим. Миграции карт нет; прежние файлы сохраняются. Повторная обработка с тем же SNP-профилем использует прежние назначения.

Формат JSON-профиля остаётся `snp-anonymizer-connectivity-v1`, профильного проекта — v2, отчёта — v2, CSV — v2. Форматы результатов и параметры обработки данных не меняются.

Профиль подготовлен по metadata-only снимку `src/anonymizer/resources/model.json`: SHA256 байтов этого локального файла — `0aaed0b2d48fdf8638f515dc534f81a7666512c00aa5ec780ffc4250da27bed2`. Это не Git SHA внешнего репозитория модели. В профиль перенесены 31 FK и 16 BK; составные проверки совпадений объявлены отдельно и не выданы за FK снимка. SHA256 нормализованного SNP v1 — `270711eaa36efb90f1c6d1d681de67bc636a541a349f021b76bbeb4e237bb286`.
